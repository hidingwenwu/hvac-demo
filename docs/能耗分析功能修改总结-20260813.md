# 能耗分析功能修改总结

## 1. 实施结论

已在 `hvac-demo` 原型工程中新增“能耗分析”一级菜单，并完成 7 个可交互页面、共享模拟数据层、统一视觉样式和自动化验收脚本。

本次按用户确认后的方案实施：沿用工程现有“主壳 + 多页面 + 共享数据层”结构，不再采用单文件交付；未提交 Git、未上传 GitHub。

## 2. 已确认并落实的方案调整

- 采用共享事实模型方案 A，`pages/_fleet.js` 是建筑、楼层、房间、内机标识和租户关系的唯一事实源。
- 房间数量按 `_fleet.js` 中实际唯一房间统计，当前为 140 个，不使用需求文档中的示例规模 618。
- “能耗分析”位于“节能策略”之后、“项目及设备管理”之前。
- 项目 `001` 作为无电表项目，电表数为 0，隐藏整个“能耗分析”菜单。
- 用户在能耗页面切换到 `001` 时，主壳自动回退到项目总览，避免停留在无数据页面。
- 电表多选采用合计口径；多电表横向对比由“对比分析”页面承担。
- 能耗群组按项目隔离，仅用于分析，与集中控制群组相互独立。
- 能耗分析专注能耗与运行指标，不读取电价配置、不计算或展示费用；平台原有“电费相关”菜单与页面保持不变。

## 4. 数据与交互自洽

- 所有空间、内机标识和租户关系读取 `_fleet.js`，页面不重复维护独立名单。
- 租户目录和租户能耗直接按每台内机的租户归属聚合；同一房间内不同租户的内机不会被合并到首台内机的租户。
- 总览、趋势、排行、结构、报表和群组查询共享同一模拟数据生成规则。
- 群组能耗严格等于当前有效成员房间的能耗之和；编辑成员后按最新成员口径重算。
- 多电表选择生成单一合计序列，电表对象名称与成员电表保持对应。
- 公区/租户区结构读取“空调与房间关系”中的公区房间配置，配置变化后分析结果同步更新。
- 运行时长按内机逐日生成并逐级汇总，房间、楼层、项目及报表结果保持非负和可加。
- 排行按当前指标（能耗或运行时长）排序并计算占比。
- 趋势粒度切换时，输入控件在日期、月份和年份之间联动，并保持合法起止值；快捷项覆盖今日、昨日、本周、本月、上月、本年和自定义。
- 按周、按月和按年查询分别严格限制为 26 个自然周、36 个自然月和 3 个自然年，不使用近似天数造成额外周期。
- 室外温度叠加仅在按时、按日粒度可用。
- 排行自定义时段直接读取用户输入的起止日期。
- 运行时长排行下钻趋势页后，汇总卡、图表和单位保持运行时长口径，不退化为能耗。
- 日报、周报、月报和年报均读取当前可见报告期控件，不使用固定查询日期。
- 报表每一行均与同对象、同时间范围的趋势查询一致，合计按当前所列对象求和，不向最后一行灌入舍入差额。
- 对象对比读取用户选择的粒度和范围，图表序列直接使用共享趋势查询结果，不再人工合成。
- 自定义两期长度不同时，汇总、图表和明细统一按较短区间对齐，并显示未参与比较的多余点位数量。
- 总览到排行、报表以及趋势对象的下钻参数均可回填，切换对象类型时不会残留上一对象。
- URL 中的对象已删除或失效时，趋势页回退项目整体并显示明确提示。
- ECharts CDN 不可用时显示图表空态，筛选、表格、分页和群组管理仍可使用。
