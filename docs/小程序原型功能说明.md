## 一、产品概述

「空调集控管家」是面向**项目管理者（物业管理员）**的微信小程序，将集控计费平台的核心能力搬到手机端，解决"不在电脑前也能管空调、查电费"的移动场景诉求。

**目标用户与核心价值（V2.0 单一身份）：**

| 角色 | 核心诉求 | 对应模块 |
|---|---|---|
| 物业管理员 | 远程开关/调温、批量群控、定时日程、节能策略、故障与离线感知、设备台账查看、电费账单查询 | 设备控制、群组管理、日程管理、节能策略、环境感知、设备管理、电费查询、个人中心 |

**计费模式覆盖：** 模拟数据内置 1 个预付费项目（开通自助充值）+ 1 个后付费项目，用于演示两种模式下的界面差异。

**页面结构（V2.0）：** 底部 3 个 Tab —— 首页 / 设备 / 我的；二级页通过页面栈右滑进入、左滑返回，模拟小程序 `navigateTo / navigateBack / switchTab` 导航行为。

## 二、登录模块

登录页为非 Tab 页（无 TabBar），未登录打开小程序一律先进入登录页；登录成功写入登录态与角色（`MP.state` 的 `loggedIn` / `role`），`switchTab` 进入首页。**V2.0 去角色化：三种登录方式成功路径统一写 `role=admin`（物业管理员），role 键保留以兼容 elec-admin 等页既有权限判断。**

### 2.1 三种登录方式

| 方式 | 交互 | 校验规则（原型） |
|---|---|---|
| 账号密码 | 账号 + 密码（必填，前端非空校验）→ 登录 | 仅认演示账号 `admin / 123456`，其余 toast「账号或密码错误」 |
| 手机验证码 | 手机号 + 验证码 +「获取验证码」（60s 倒计时，每秒更新「Ns 后重发」） | 手机号需满足 `^1\d{10}$`；验证码任意 6 位数字可过（发送时 toast「验证码已发送（演示环境任意 6 位）」） |
| 微信一键登录 | 微信绿按钮 → 模拟授权弹窗（头像占位 + 昵称「微信用户」+ 申请获取昵称头像文案，按钮「允许 / 拒绝」） | 允许后判断微信绑定状态：已绑定 → 直接登录；未绑定 → 进入「绑定账号」页 |

### 2.2 演示账号

| 演示账号 | 账号 / 密码 | 身份 |
|---|---|---|
| 物业管理员 | `admin` / `123456` | 全部功能（含电费账单） |

V2.0 去角色化：登录即物业管理员身份，原「演示账号快捷登录」双卡片区（admin/tenant 一键登录）已删除，租户演示账号不再有效。

### 2.3 微信绑定与双端适配预留

- 微信首次登录需绑定已有平台账号（账号/密码，必填校验，仅认演示账号）；绑定成功写入 `MP.store` 的 `wxBound`，之后微信一键登录免绑直入（V2.0 起不再记录绑定账号角色，登录统一为物业管理员身份）。
- **Web 端适配预留**：Web 端登录页后续新增「微信扫码登录」入口，扫码后同样走账号绑定流程，小程序与 Web 端共用一套绑定关系（原型仅作逻辑演示）。

### 2.4 页面信息

- 顶部品牌区：LOGO 占位（蓝色圆角方块 + ❄）+ 产品名「空调集控管家」+ 副标题「空调集中控制 · 节能管理移动助手」；底部版权 `© 2026 青岛飞奕科技有限公司`。
- 页面文件：`mp/pages/login.js`（登录）、`mp/pages/login-bind.js`（绑定账号）。

## 三、首页

首页为 Tab 主页（`mp/pages/home.js`），是移动端专属页面，Web 端无对应页。R3 起界面对齐现行集控小程序首页，自上而下七个区块 + 下拉刷新。**全部统计数字实时计算**（设备相关取自 `MP.data.devices`，日程/群组数取自 `MP.q`），无任何写死的演示数字。

### 3.1 自定义 banner 条与项目切换

- 顶部 56px banner 卡片：左侧企业 LOGO + 当前项目名（含计费模式副标题，预付费项目标注「已开通自助充值」）+ 右侧「切换 ⌄」入口。
- **LOGO 由 Web 端项目管理按项目配置**（`MP.data.projects[].banner`），客户可自定义企业标识；未配置时使用灰底「LOGO」占位。
- 点击 banner 弹出底部 ActionSheet 列出全部项目 → 选择后写入 `MP.state.projectId` 并重渲染本页，toast「已切换至 XX」；首次进入无选中项目时默认取第一个项目（p1）。

### 3.2 快捷功能卡

3 张横排（彩色圆角底块 52px + 白色 SVG 图标 + 名称），对齐现行小程序首页顶部三入口：

| 快捷卡 | 色块 | 跳转 |
|---|---|---|
| 空调控制 | 主色蓝渐变 | `MP.switchTab('device')` |
| 定时任务 | 橙渐变 | `MP.go('schedule-list')` |
| 群组管理 | 绿渐变 | `MP.go('group-list')` |

### 3.3 室内机设备状态卡

- **左侧环形进度图**：纯 SVG 实现（非 canvas），半径 54px、stroke-width 10、round 端点，灰底环 + 主色进度环，-90° 起笔自顶部；进页时 `stroke-dashoffset` 600ms 扫入动画。**中心大字 = 可用设备总数（在线数）**，进度 = 在线率（在线数/设备总数）。
- **右侧 2×2 四格统计**：运行（主色）/ 关机（灰）/ 故障（红）/ 离线（深灰），每格大数字 + 小标签 + ›。口径与设备页状态筛选 chips 一一对应：运行 = 在线且开机，关机 = 在线且关机，故障为独立维度（故障机可能同时处于开机态，与运行格存在交叉），离线 = 不在线；运行 + 关机 = 在线数 = 环形中心数。**点击任一格跳转设备 Tab 并预设对应筛选**（经 `MP.state.devFilter` 一次性传递，设备页读取后清除）。
- **底部两个 chips**：平均设定温度 / 平均室内温度，取在线且开机设备的实时平均，保留 1 位小数；无在线开机设备时显示「--」。

### 3.4 锁定状态卡

模式锁定数量 / 温度锁定数量 / 开关锁定数量三格大数字，按设备 `lock` 字段实时统计：`lock.mode` 真值数 / `lock.tempHi` 或 `lock.tempLo` 非空数 / `lock.power` 真值数。

### 3.5 日程/群组概览卡

两张纵排概览卡，整卡可点：日程管理卡显示定时任务数量（`MP.q.schedules().length`）+「查看全部 ›」→ 日程列表；群组管理卡显示当前群组数量（`MP.q.groups().length`）+「查看全部 ›」→ 群组列表。走覆盖层读取，增删改后回首数字即更新。

### 3.6 全部功能宫格

2 行 4 列，图标 + 文字，共 8 项（R3 色板收敛为 8 个色相区分色：蓝/青/橙/绿/紫/金/玫红/灰蓝，原深蓝底块与主蓝色相重复已修正）：

| 宫格项 | 跳转 | 说明 |
|---|---|---|
| 空调控制 | `MP.switchTab('device')` | 设备 Tab |
| 群组管理 | `MP.go('group-list')` | 群组管理 |
| 日程管理 | `MP.go('schedule-list')` | 日程管理 |
| 节能策略 | `MP.go('strategy-list')` | 节能策略 |
| 环境感知 | `MP.go('env-list')` | 环境感知设备 |

**分区骨架**

| 分区 | env 环境感知联动 | wind 风水联动 | load 负荷调控 | ultimate 极致节能 |
|---|---|---|---|---|
| ① 策略类型 | 4 chip 单选，编辑态只读（「创建后不可修改」） | 同左 | 同左 | 同左 |

**②基础信息的关键控件**

- **生效日期 / 时间范围**：两个 `date` 输入 + 「至」，校验结束不早于开始。
- **生效时间**：两个下拉，**5 分钟粒度**（开始 00:00~23:55；结束额外含 **24:00**，表示当日 24 点整），校验结束晚于开始。
- **周重复时间 / 周运行时间**：七天多选格（周一~周日）+ 四个快捷按钮 `工作日 / 周末 / 全选 / 取消`，默认工作日；至少选 1 天。
- **排除日期**：`date` 输入 + 「+ 添加」+ 「**一键排除节假日**」；已选日期以 chip 呈现并标注节日名（如 `2026-10-01（国庆节）`），点 × 删除。校验排除日期须在生效日期范围内；一键排除只写入生效期内的节假日。节假日库 `MP.data.holidays` 含端午/中秋/国庆/元旦四组。
- **执行周期**（wind）：`按天 / 按小时` segmented。**空调类型**（load）：水机 / 氟机 / 直膨机 / 温控器。

**③-env 如果满足条件**

- 条件行动态列表，行首前缀第一行为「如果」、第 2 行起为「且」（**多条件为「且」关系**）。
- 条件类型四选一：**人在状态 / 门窗状态 / 温度 / 湿度**；**同一类型只能配一次**（已被占用的类型在其它行的下拉中 disabled），**最多 4 条**（已满时点「＋ 且满足条件」提示「4 类触发条件均已配置，不能继续添加」）；删至 1 条时提示「至少保留 1 个触发条件」。
- 人在状态 = `有人 / 无人`、门窗状态 = `开启 / 关闭`（segmented 单选）；温度 / 湿度 = 比较符下拉（`高于 > / 低于 < / 升高到 ≥ / 降低到 ≤`）+ 阈值数字输入（温度 -10~50 ℃、湿度 1~99 %，均须整数）。
- **持续满足条件**（虚线卡片）：勾选后显现「持续时长」输入（1–60 分钟）；说明文案随开关切换 —— 未勾「满足条件立即执行」/ 已勾「满足条件后 N 分钟再次确认，仍然满足条件再执行」。

**③-env 则执行如下动作**

- 有序动作链，行首为序号圆标（1、2、3…），**最多 16 步**；动作类型三选一：
  - **空调控制**：开关机（开关不控制/开机/关机）、空调模式（模式不控制/制冷/制热/送风/除湿）、温度（16–30℃ 整数，占位「温度不控制」）、风速（风速不控制/高/中/低）
  - **锁定控制**：开关机锁定（开关机不锁定/禁止关机/禁止启动，对齐空调控制卡片口径）、模式锁定（制冷/制热/送风/除湿 多选 chips，未选=不锁定）、温度锁定（温度不锁定/锁定温度范围）→ 选「锁定温度范围」后显现**下限/上限两个下拉**（16–31℃）
  - **延时**：5–240 分钟整数
- 「＋ 添加动作」默认类型规则照搬 Web：**上一个是控制类动作（空调控制/锁定控制）则新增延时，否则新增空调控制**。
- 校验（逐条对齐 Web）：至少 1 个动作；**相邻两个动作不允许相同**；**控制类动作（空调控制/锁定控制）后必须紧跟一个延时（最后一个动作除外）**；**最后一个动作不能是延时**；每个空调控制动作**至少设置一个控制参数**；**制热不能与制冷或除湿同时锁定**；锁定温度下限不得高于上限。

**③-wind 执行策略 / ③-load 负荷调控目标 / ③-ultimate 空调控制配置**

- **wind**：「选择策略」下拉引用策略库 `MP.data.windLib`（7 条，照搬 Web 端策略名），选中后下方**只读展示该策略的五项参数**：设备类型 / 运行模式 / 温度设定 / 风速 / **联动水阀**。风水联动的两级结构（策略模板 + 任务绑定）是它与其余三类最大的差异，策略模板本身仍由 Web 端「策略管理」维护，小程序只引用不编辑。
- **load**：负荷调控目标(kW)*（数字 + kW 后缀）、负荷调控目标(幅度)*（数字 + % 后缀）、策略*（温度上调 / 风速限制 / 分组轮停 / 锁定设定温度，四选一，策略自带调控步长）、来源（手动创建 / 需求响应）。
- **ultimate**：下发间隔*（**5–120 分钟**整数，附 Web 原文示例说明）+ 开关机 / 空调模式 / 温度（16–30℃，step 0.5）/ 风速，四项空值项文案均为「**不设置**」，**四项至少需要设置一项**。

**④生效范围**

- env / ultimate：**楼栋 → 楼层 → 房间三级折叠树**（复用 R7 绑定页的 `.mp-arb-row` 三级行），楼栋/楼层带三态勾选可整选（父级半选态用 `.mp-check.half`），卡头实时显示「已选 N 个房间」；未选提示「请至少选择一个房间」。
- wind：房间范围单选下拉（`全部房间` + 各楼层）。load：调控范围多选列表（各楼层 + 已选计数），未勾提示「请勾选调控范围」。

**保存与摘要**

- 底部固定主按钮：**ultimate 为「保存并启用任务」**（照搬 Web 原文），其余三类为「保存」。
- 校验不通过时 toast 首条错误（Web 为顶部错误框逐条罗列，移动端改为单条 toast 即时提示）；通过后按类型重新生成摘要 `desc`（口径同 Web 列表「控制策略」列，如「检测到无人并持续满足 10 分钟时，将空调关机。」）与 `targetName`，`saveStrategies` 持久化 → `MP.back()` + toast。
- 新增 id 取 `'st'+Date.now()`，默认启用；编辑保存整条替换，保留原启停状态。
- **类型切换**：仅新增态可切；切换后整表重置为该类型空白初值，**已输入的任务名称跨类型保留**，避免误清。

## 九、设备管理

对应 Web 端「项目及设备管理」的空调与房间关系（`device-ac-room.html`）与控制器（`device-controller.html`）两页，小程序端拆为三个二级页：空调与房间关系（`mp/pages/ac-room.js`）、绑定空调（`mp/pages/ac-room-bind.js`）、控制器（`mp/pages/controller.js`）。入口：首页宫格「空调房间绑定 / 控制器」。

**楼栋/楼层/房间三级注册表（R7 新增）**：`MP.data.buildings` 为绑定选点用的只读注册表，与 `device.room` 扁平字符串**并存**——

|---|---|---|
| 楼栋 | `{id,name,floors[]}` | 1号楼 / 2号楼 / 3号楼（3 个） |

| 房间 | `{id,name}` | 合计 9 个 |

- **房间显示名 = 楼层名 + 房间名拼接**（不含楼栋名），如「一楼」+「大堂」=「一楼大堂」。1号楼下 6 个房间是现状 6 个扁平 `room` 字符串的原样结构化，拼接结果与现有设备的 `room` 取值**逐一对应**，已绑定设备零回归；2号楼/3号楼的 3 个房间为新增空房间（尚无设备绑定），供演示「从空房间开始绑起」。
- 因绑定存储层仍以扁平房间名为 key，**全楼盘范围内房间显示名必须互不重复**，本注册表已保证唯一。
- `MP.acRoom.buildings()` 返回全量注册表（含空房间），区别于只列「已有设备绑定」房间的 `MP.acRoom.rooms()`；`MP.acRoom.locate(房间名)` 反查该房间所属楼栋/楼层，返回 `{building,floor}`，找不到返回 `null`（调用方静默降级，如「未绑定设备」这类非真实房间名）。
- **controller↔device 关联（R7 新增）**：`MP.data.controllers[].deviceIds` 为控制器接控的设备 id 数组，与既有 `acCount` 数值一一对应（c3 因新增 d19/d20 两台，`acCount` 由 3 改为 5），供绑定页「按控制器分组」反查；`controller.js` 页面直读 `acCount` 展示，本身无改动。

### 9.1 空调与房间关系（ac-room）

- **顶部「＋ 绑定空调」主色按钮** → 进入绑定操作页。
- **按房间分组的折叠列表**：房间行（展开箭头 + **楼栋小标注** + 房间名 + 已绑 N 台）点击折叠/展开；展开显示已绑空调行——设备名、SN、在线/离线 tag，右侧红色「解绑」文字钮 → confirm 二次确认「将 X 从 房间Y 解绑？」→ 持久化 + 重渲染 + toast。
- **楼栋小标注（R7）**：房间名前挂一枚淡蓝小标签显示所属楼栋（经 `MP.acRoom.locate` 反查，如「1号楼 一楼大堂」），视觉量级对齐 `.mp-sub`/`.mp-tag`，不抢房间名主体地位；反查不到时（如「未绑定设备」分组）不显示标注，文案原样保留。
- **底部「未绑定设备」分组**：room 为空的设备单列一组（黄色「未绑定」tag），便于看到可绑资源；无未绑定设备时该组不显示。

### 9.2 绑定空调（ac-room-bind）

**① 房间选点（进入本页默认状态）**

## 十、电费查询

对应 Web 端「电费相关」的电费查询（`elec-query.html`）与租户管理（`elec-tenant.html`），小程序端为管理员单一视角的电费查询能力，三个二级/三级页：管理员账单（`mp/pages/elec-admin.js`，二级页）、租户台账列表（`mp/pages/elec-tenant-list.js`，二级页）、租户详情只读（`mp/pages/elec-tenant-detail.js`，三级页）。**入口唯一：首页宫格「电费查询」固定进入管理员账单（elec-admin）**，租户台账列表/详情从账单页逐级下钻进入。

**R6 改造背景**：V2.0 去角色化后小程序不再演示"租户第一人称"身份，原「租户余额」（`elec-tenant.js`，含自助充值入口）与「自助充值」（`elec-recharge.js`）两页面向租户本人操作，与管理员单一身份场景不符，长期无页面入口。R6 明确产品定位——**物业管理员可以查看全部租户账单**，因此电费模块保留"管理员查看租户台账"的能力，但改造为管理员视角的**多租户列表**：原两页下线，新增 elec-tenant-list（租户台账列表）与 elec-tenant-detail（租户详情只读），管理员可逐一查看名下所有租户的余额/账单情况，但**不提供任何代客充值或编辑操作**（该操作面向租户本人，超出管理员场景）。

**数据模型**：`MP.data.bills`（month/tenant/tenantId/usage/amount/status）为账单演示数据（仅 2026-08/2026-07 两个月），新增 `tenantId` 字段关联租户；`MP.data.tenants` 为租户台账数组（R6 由单一 `tenant` 对象改造而来），预付费租户（`feeMode:'prepaid'`）带 `balance/remind/records`，后付费租户（`feeMode:'postpaid'`）不带余额、账单走 `bills[].tenantId` 关联查询。租户台账查询统一走 `MP.q.tenants(projectId)/tenant(id)/tenantBills(id)` 三个只读方法，**本模块 R6 起无 `mp_store` 覆盖层**——纯只读查看，不再有 `balance()/tenantRecords()/recharge()` 等增删改接口。

### 10.3 租户详情·只读（elec-tenant-detail，R6 新增）

## 十二、全局交互规范

### 12.1 路由与导航

- 页面注册契约：`MP.pages.<name> = { title, tab, note, render(el,params), mount(el,params) }`。
  - `title`：顶部导航栏标题；`tab:true` 表示 Tab 主页（显示 TabBar、隐藏返回键）；`note` 为本页改造说明（`[{type:'简化|优化|新增|删减',text}]`），有 note 的页面导航栏右侧显示 ⓘ 按钮。
  - `render` 输出 HTML，`mount` 绑定事件；每次进入页面都会重新执行。
- 导航 API（对应微信小程序语义）：
  - `MP.go(name, params)` → `navigateTo`，新页面右滑进入（200ms）。
  - `MP.back()` → `navigateBack`，当前页左滑退出。
  - `MP.switchTab(name)` → `switchTab`，页面栈重置到 Tab 主页。
- URL hash 与页面名同步（`#/home` 等），刷新可恢复到 Tab 页；未登录统一兜底进登录流程。

### 12.2 页面转场

- 二级页进入：`.pg-in-right`，从右 100% 滑入；返回：`.pg-out-left`，左移 30% 淡出；动画时长均 200ms。

### 12.4 主题与热区

- 浅色主题（**R8 起对齐网关调试小程序 `gwdbg-demo` 的蓝白体系**）：页面底 `#F3F6FA`、卡片 `#FFFFFF` + 1px 描边 `rgba(225,230,238,.9)`、主色 `#2457D6`（淡蓝底 `#EDF3FF`）、状态色 `#22A06B / #BB7414 / #D9485F`、文字 `#17233A / #6D788B / #9CA5B4`、边框 `#E7EBF1`（变量统一定义在 `mp/mp.css` 的 `:root`）。
- **卡片规格**：14px 圆角 + 1px 淡描边 + 柔和大扩散阴影 `0 8px 24px rgba(28,49,81,.06)`；**主按钮**为实心主色 + 主色投影 `0 8px 20px rgba(36,87,214,.2)`（R8 前为线性渐变），按下 `scale(.97)`。
- **选中语言全站统一**：`主色描边 + 淡蓝底 + 主色文字 + 700 字重`；卡片级（设备卡）另加 2px 主色光环 `0 0 0 2px rgba(36,87,214,.12)`。chips 不再使用主色实心反白。
- **字重梯度**：卡片标题 / 列表主文本 700–650，大数字 500（tabular-nums），说明文字 400；信息层级主要靠字重区分而非纯字号。
- 主要可点元素（按钮 / 列表项 / 表单行 / Tab / 步进器）热区 ≥44px；组件类统一 `mp-` 前缀。
- **紧凑控件取舍**：筛选 chips（`.mp-chip`，30px）、分段器项（`.mp-seg-i`，36px）、卡片电源钮（`.mp-pow`，40px）为信息密度取舍，自身尺寸不足 44px，但连同所在行高与 padding 实际可点区域为 36–44px，与微信小程序常见密度一致；主要操作路径不受影响。

### 12.5 图标体系（R2）

- **全站统一 SVG 线性图标**，不再使用 emoji/字符图标（°C、‹ ›、✓ 等排版字符除外）。图标库集中在 `mp/icons.js`，壳在 `data.js` 之后、各页面之前引入。
- **绘制规范**：24×24 viewBox、`fill:none`、`stroke:currentColor`（颜色随 CSS `color` 继承）、`stroke-width:1.5`、`stroke-linecap/linejoin:round`，手写简洁 path，风格统一。
- **调用方式**：`MP.icon(name[, cls[, sw]])` 返回 SVG 字符串 —— `name` 图标名；`cls` 附加尺寸类（`xs`=12px / `sm`=16px，默认 20px，容器级尺寸由所在组件 CSS 覆盖，如 TabBar 22px、宫格 23px、空态 46px）；`sw` 覆盖描边宽度（电源键用 2）。未知名返回空串兜底。
- **图标清单（26 个）**：
  - 导航：`home` 首页 / `device` 设备（空调挂机）/ `me` 我的
  - 功能：`group` 群组 / `schedule` 日程 / `strategy` 节能策略 / `env` 环境感知 / `bind` 房间绑定 / `controller` 控制器 / `elec` 电费 / `more` 九宫格
  - 控制：`power` 电源 / `snow` 制冷 / `sun` 制热 / `fan` 送风 / `drop` 除湿
  - 状态：`lock` 锁定 / `alert` 告警 / `check` 对勾 / `arrow` 右箭头 / `back` 返回
  - 补充：`search` 搜索 / `info` 说明 / `chat` 微信 / `bill` 账单 / `wallet` 钱包
- 首页宫格图标为「彩色圆角底块 + 同色 SVG 图标」，底色板类 `gi-b/c/g/o/p/y/d/s` 定义在 `mp/mp.css`。
