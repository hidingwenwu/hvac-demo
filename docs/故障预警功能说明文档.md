# 空调节能监控平台-故障预警功能说明文档

> 版本:V3.4(2026-08-26) · 配套交互原型:https://github.com/hidingwenwu/hvac-demo.git
> (下载后,打开 hvac-demo.html → 菜单「故障预警」)

# 一、功能概述

## 1.1 要解决的问题

平台现有故障能力分散在三处(铃铛异常列表、计费异常统计、空调故障记录),带来三个根本问题:

1. 入口分散——用户不知道去哪里看全部故障;
2. 不分轻重——所有异常同等对待,影响运行的故障容易被淹没;
3. 被动发现——只能等用户登录后偶然看到,无法主动触达责任人。

## 1.2 建设方案

建设统一的故障预警中心,做四件事:

| 动作 | 内容 |
| ---- | ---- |
| 整合 | 全部故障统一归集到「故障预警」菜单组,按统一分类分级管理 |
| 分级 | 全部故障划分为三档:故障(红)/ 警示(橙)/ 提示(蓝) |
| 触达 | 短信推送主动触达(推送范围按项目配置)+ 顶部铃铛红点站内提醒;**不单独建设站内信/消息中心** |
| 闭环 | 处理状态流转、处理留痕,未处理数全站实时联动 |

# 二、分类与分级

## 2.1 故障分类(一期范围)

| 故障类别 | 子类   | 一期故障项                                            | 责任角色     |
| ---- | ---- | ------------------------------------------------ | -------- |
| 项目运维 | 基础配置 | 控制器离线、电表离线、环境感知设备离线、控制器存储空间不够、内机未绑定建筑物           | 项目初始维护人员 |
| 项目运维 | 计费分摊 | 缺少抄表记录、电表未绑空调系统、电表可能绑错空调系统(判定信号:有电量没当量 / 有当量没电量) | 飞奕计费运维   |
| 空调故障 | —    | 网关/控制器上报的空调故障代码,按代码库定级                           | 客户/维保方   |

非计费项目全链路隐藏计费分摊相关内容(铃铛、列表、筛选、总览、推送范围)。

## 2.2 故障等级与判定逻辑

| 等级 | 含义 | 颜色 | 默认推送 |
|---|---|---|---|
| 故障 | 影响正常运行,必须处理 | 红 | ✅ |
| 警示 | 可继续运行,存在隐患 | 橙 | ⬜ 可选 |
| 提示 | 提示性信息,无需刻意处理 | 蓝 | ⬜ 可选 |

- **项目运维故障**:等级按故障名称内置映射,映射表见 7.1(一期无提示级);
- **空调故障**:按项目逐条判定,优先级从高到低:**项目屏蔽(不预警、不计数、不推送)> 项目自定义等级 > 通用代码库 > 未收录默认警示**;
- **变更生效范围**:项目自定义等级与通用代码库更新后,**即时作用于存量未处理记录**的展示与统计;已发送的短信推送不追溯;
- **术语约定**:等级措辞全站统一为「故障/警示/提示」;「基础配置/计费分摊」维度统一称**故障子类**(避免与「故障类别」一词两义)。

# 三、数据口径与计算规则(全局统一)

本章是所有计数、图表、列表的唯一口径来源;任一处理/忽略/屏蔽操作后,铃铛、统计卡、列表实时联动刷新。

| 指标             | 计算规则                                                                      |
| -------------- | ------------------------------------------------------------------------- |
| 时间基准           | 全站统一采用平台服务器时间(北京时间);"当日"按自然日 00:00 起算                                     |
| 统计范围           | 当前项目的故障记录;**项目屏蔽故障码的记录一律不计**;非计费项目不计计费分摊类(计费属性取项目管理中的计费配置)                |
| 未处理总数          | 无处理结果的记录数(状态为「未处理」+「已恢复待确认」)                                              |
| 今日新增           | 故障发生时间为当日(00:00 起)的记录数,不区分处理状态                                            |
| 等级计数(故障/警示/提示) | 未处理记录按等级聚合,项目运维与空调故障合计                                                    |
| 故障恢复时间         | 项目运维=异常消失时间;空调故障=故障码复位上报时间;恢复后状态转「已恢复待确认」(仍计入未处理),人工确认后闭环                 |
| 持续时长           | (故障恢复时间,未恢复取当前时间)− 故障发生时间                                                 |
| 趋势统计-新增故障      | 记录按「故障发生时间」自然日聚合计数                                                        |
| 趋势统计-处理完成      | 已处理记录按「处理时间」自然日聚合计数                                                       |
| 故障分类占比         | 当前**未处理**记录分别按类别、按等级聚合(已处理、已忽略、屏蔽记录不计入)                                   |
| 状态有效性          | 处理/忽略状态**仅对本次故障有效**(以故障发生时间标识):同类故障复发(故障发生时间前移)后原状态自动失效,记录重新计入未处理并可再次触发推送 |
| 数据隔离           | 处理状态、推送配置、项目级故障码配置均**按项目隔离**;同一故障在 A 项目处理不影响其他项目                          |

「未处理」为全局统一口径(=未处理+已恢复待确认):计数、列表默认筛选、所有深链跳转保持一致,**任何入口看到的数字与落地列表条数一一对应**。

# 四、全局入口

## 4.1 菜单与角色

```
故障预警
├─ 故障总览      终端管理员、技术支持、经销商、超管
├─ 故障详情      终端管理员、技术支持、经销商、超管(项目运维 / 空调故障双 Tab)
└─ 故障推送      仅技术支持、超管(其他角色不可见;该约束不在页面内展示)
```

## 4.2 顶部铃铛(站内提醒)

铃铛承担全部站内提醒职责,规则如下:

**红点**

- 当前项目存在未处理故障(口径见第三章)时,铃铛图标显示红点,红点不显示数量;
- 红点只依据未处理口径,与短信开关、推送范围等任何推送配置无关;登录、切换项目后立即按当前项目刷新。

**登录提醒**

- 仅**项目物业管理员(项目主账号)**:登录后若存在未处理故障,自动展开铃铛面板一次(提醒项目故障内容);
- 面板在以下任一情况自动隐藏:点击页面其他位置(含子页面区域)、刷新、跳转其他页面;每个登录会话最多自动展开一次;
- 其他角色登录不自动展开,可手动点击铃铛查看。

**面板内容(故障摘要)**

面板只承担「看一眼概况」的职责,不提供故障明细、不提供筛选跳转:

- 面板标题「故障摘要」;
- 三张统计卡:**今日新增 / 未处理总数 / 故障级**(口径见第三章),纯展示,点击不跳转;
- 底部入口「**故障总览**」:点击跳转故障总览页。

处理/忽略故障后,红点与卡片数字实时刷新。

# 五、页面功能

## 5.1 故障总览

页面自上而下四块:统计卡、故障趋势统计、故障分类、最近故障。

**统计卡(7 张)**

今日新增 / 未处理总数 / 项目运维 / 空调故障 / 故障级 / 警示级 / 提示级,口径见第三章;等级三卡为项目运维+空调故障合计。

统计卡**纯展示,点击不跳转**;查看明细经左侧菜单进入故障详情页。

**故障趋势统计**

- 柱状图双序列:新增故障(蓝)/ 处理完成(绿),口径见第三章;
- 图表标题右侧切换**近 7 日 / 近 30 日**;柱体悬停显示日期与数值。

**故障分类(双饼图)**

- 左图「故障类别」(项目运维/空调故障),右图「故障等级」(故障/警示/提示),统计**当前未处理故障**的分布;
- 鼠标划过扇形显示条数与占比(百分比,1 位小数);环心显示未处理总条数;图下方注释说明统计口径。

**最近故障**

- 跨类合并,按故障发生时间倒序取 10 条;
- 每行从左到右依次为:**故障类别**(项目运维/空调故障)、**故障等级**(故障/警示/提示标签)、**故障名称**(项目运维)或**故障代码**(空调故障)、**发生对象**(项目运维=故障对象;空调故障=楼栋-楼层-房间(内机全地址))、**故障发生时间**(完整时间戳);
- 点击某行**按该记录定位**:跳对应 Tab 并带入对象/内机地址筛选、状态=全部(已处理记录也能直达查看)。

## 5.2 故障详情(项目运维 | 空调故障 双 Tab)

**深链参数**

支持以 URL 参数直达定位:`tab` / `level` / `status`(缺省=未处理;显式传空=全部)/ `today`(当日范围+全部状态)/ `obj`(运维记录定位)/ `addr`(空调记录定位)。当前页面入口为「最近故障」的记录定位(见 5.1);`level`/`today` 等参数为页面间直达能力(预留)。

- `level` 深链同时作用于两个 Tab(同步筛选与档位卡高亮),落地优先有数据的项目运维 Tab,项目运维该等级为 0 时直达空调故障 Tab;`today` 深链同理。

**项目运维 Tab**

- 顶部三档统计卡:各等级未处理数;点击=快捷筛选该等级,再次点击取消;
- 筛选项:故障等级 / 故障子类 / 故障名称(随子类联动)/ 故障对象(关键字)/ 状态(默认「**未处理**」=未处理+已恢复待确认;可单选已恢复待确认/已处理/已忽略)/ 故障发生时间范围 / 故障恢复时间范围(仅已恢复记录参与命中);
- 列:多选框 / 序号 / 故障等级 / 故障子类 / 故障名称 / 故障对象 / 故障发生时间 / 故障恢复时间(未恢复显「—」)/ 持续时长 / 状态 / 处理人 / 操作(详情·处理·忽略);**不设故障描述列(详情弹窗亦无故障描述);列表默认按故障发生时间倒序**;
- 字段语义:**故障发生时间=本次故障开始时间;故障恢复时间=异常消失时间**;
- 详情弹窗:故障类别/子类、等级、名称、对象、故障发生时间、**故障恢复时间(常显,未恢复显「—」,与列表一致)**、持续时长(仅时长数值)、状态与处理留痕;「已恢复待确认」状态额外提示:需人工确认故障期间数据已补全(如当量/抄表自动补拉结果)后点「处理」闭环。

**空调故障 Tab**

- 左侧**建筑物信息三级树**(楼栋/楼层/房间,页面加载即渲染,与集中控制等页同一组件):点选任意节点即按该节点筛选,再次点击取消;
- 顶部三档统计卡同上;筛选项:故障等级 / 品牌 / 故障代码 / 内机全地址 / 状态(含已恢复待确认)/ 故障发生时间范围 / 故障恢复时间范围(不设房间筛选项,房间维度经建筑树筛选);
- **已屏蔽记录不展示**:项目屏蔽故障码的记录**不再出现在本列表**(任何筛选条件下均不可见),与计数口径一致——屏蔽即不再记录、不计数、不推送;
- 列:多选框 / 序号 / 楼栋 / 楼层 / 房间 / 内机全地址 / 品牌 / 故障代码(纯文本,不可点击)/ 故障等级 / 故障发生时间 / 故障恢复时间(未恢复显「—」)/ 持续时长 / 状态 / 操作(详情·处理·忽略);**不设故障名称列——故障描述仅在详情弹窗展示,明细经操作列「详情」查看;列表默认按故障发生时间倒序**;
- 详情弹窗联查代码库:故障描述(=代码库故障名称,未收录显「未知故障」)/ 排查建议(通用库内容;**未收录代码默认按警示处理,并在排查建议内提示联系飞奕维护至通用故障码库**);**故障等级仅展示等级标签**(判定依据不附说明文案);故障恢复时间常显(未恢复显「—」),持续时长仅展示时长数值;
- **恢复口径与项目运维一致**:故障码复位上报即记录故障恢复时间,状态自动转「已恢复待确认」(仍计入未处理),需人工确认现场机组恢复正常后点「处理」闭环;恢复后同码再次上报视为新故障。

**批量操作(两个 Tab 均支持)**

- 列表多选(行首复选框+表头全选)后可**批量处理 / 批量忽略**;仅对选中项中未闭环(未处理/已恢复待确认)的记录生效,已处理/已忽略自动跳过;批量处理共用处理弹窗(一条备注/处理人应用于全部选中项),批量忽略二次确认后生效;
- **不设批量删除**——批量忽略即起到批量清理效果(不再计入未处理,记录在「全部」状态下留痕可查,同类故障复发自动重新告警);计划性检修等批量噪音场景亦经批量忽略处理(不单独建设维护窗口)。

**状态机(单值)与处理交互**

```
未处理 ──处理──▶ 已处理          处理弹窗:顶部故障摘要(项目运维=故障对象:故障名称,一行;空调故障=内机位置+内机地址+故障代码+故障描述+排查建议),处理备注必填,处理人默认当前账号(可改),留痕可查
未处理 ──忽略──▶ 已忽略          忽略用于误报/计划性噪音,二次确认后生效
异常自动消失   ▶ 已恢复待确认     项目运维=异常消失,空调故障=故障码复位;仍计入未处理,人工确认后走「处理」闭环
同类故障复发   ▶ 恢复未处理       原「已处理/已忽略」自动失效(仅对本次故障有效),重新告警并可再次推送
```

处理状态按项目隔离,跨项目互不影响。

## 5.3 故障推送(仅技术支持、超管)

本页全部内容均为**短信推送管理**(站内提醒由铃铛红点承担,见 4.2,不产生推送流水)。

- 筛选:项目名称(**支持手动输入或下拉选择**)/ 短信推送 / 故障等级(按推送范围)/ **推送方式**(实时推送/每日汇总);
- 列:项目名称(纯文本展示,不可点击)/ 短信推送(开关)/ 推送范围 / 推送方式 / 最近推送 / 操作(**推送配置** · 推送记录 · 故障代码库);
- 行内开关即时生效;开启短信但未配置接收人时提示先完善;
- **推送配置**(抽屉,项目级):
  - 启用短信推送开关;
  - **推送范围**:故障等级 × 故障类别勾选,**作用于短信推送**;保存校验:等级、类别至少各选一项;默认仅「故障」级;**顶部铃铛红点不受此范围限制**(始终按未处理全局口径提醒);
  - 接收人(平台账号选择 或 手动录入姓名+11 位手机号,可多个、按手机号查重,**上限 20 人/项目**,默认值可后台调整);**手动录入的手机号须先通过短信验证码验证**——发送验证码 → 回填校验通过后方可添加(验证码 6 位、有效期 5 分钟、60 秒内不可重复发送,更换手机号后原验证码作废);平台账号手机号已验证,选择添加无需再次验证;
  - 推送策略:推送方式(实时 / 每日汇总:每天设定时刻合并为一条,**时刻可选范围 5:00-12:00**,汇总内容为**前一个自然日**(0:00-24:00)新产生的故障预警;设定时刻为短信**发起推送**时间,实际到达手机的时间取决于运营商网络,可能略有延迟——页面在选中每日汇总时展示该说明)、免打扰时段(**仅实时推送方式下可设定**,选择每日汇总时不展示该设置;时段内不发送、时段结束不补发;勾选「**故障级豁免**」后故障级预警不受免打扰限制仍照常推送——**豁免仅决定是否发送短信**,平台内记录与统计不受影响);
- **短信推送触发规则**:新预警产生且命中推送范围 → 按推送方式发送;**内置去重规则见 7.3(后台默认逻辑,无配置项,页面不展示提示语)**;
- **推送策略适用边界**:推送策略**仅作用于短信通道**;生效优先级:内置去重 → 推送方式 → 免打扰;**免打扰(含故障级豁免)仅对实时推送生效,每日汇总无免打扰设置**;
- **不单独建设维护窗口**:计划性检修等批量噪音场景,经故障详情页**批量忽略**处理(见 5.2);
- **推送记录**(按项目弹窗):故障等级(与故障详情口径一致;每日汇总短信覆盖各级别、无单一等级,**统一按「提示」级记录**) / 发送状态 / 接收对象 / 时间筛选;短信发送流水,状态含发送中 / 已发送 / 发送失败。

## 5.4 故障代码库(弹窗维护,按项目隔离)

- 入口:故障推送页行内「故障代码库」,按**所在行的项目**打开。弹窗标题「**故障代码库(当前项目:xxx)**」+ 小字「配置仅对当前项目生效」;
- **故障码大小写规则**:录入保留原始大小写;匹配时精确优先,精确不中且该品牌下仅大小写不同的库内码唯一时按不区分大小写容错命中;**大小写并存码严格区分**(海信 EE=压缩机保护(故障)/Ee=EEPROM 数据错误(提示),另有 B1/b1、B5/b5),录入并存码时防呆校验,要求按设备上报大小写精确填写;
- 通用代码库由后台统一维护(含故障名称、故障原因与排查建议);**通用库未收录的故障码需要监测时,不在项目端添加,联系飞奕维护至通用故障码库**(维护后自动纳入全部项目监测范围);本页仅维护项目级两份清单:
- **项目自定义**:仅用于**故障等级自定义**(场景:通用代码库等级与本项目认定不同)。表单仅 **空调品牌 + 故障码 + 自定义等级** 三项(名称/描述/排查建议一律联查通用库);输入品牌+码后即时校验:通用库有此码 → 展示通用等级并可自定义;**通用库无此码 → 不可添加**,提示联系飞奕维护至通用故障码库;列:序号 / 品牌 / 故障代码 / 故障名称(通用库)/ 通用等级 / 本项目等级 / 操作(编辑·删除,删除后按通用等级生效);
- **项目屏蔽**:仅需品牌+故障码;屏蔽后该码在本项目**不再产生预警记录、不产生计数、不参与等级统计、不触发推送**;屏蔽前已产生的历史记录同步从故障详情列表移除(不再展示);
- **屏蔽与项目自定义互斥**:同码存在项目自定义等级配置时,屏蔽前二次确认,确认后移除该配置;**取消屏蔽后不自动恢复原配置**(按通用代码库等级生效,如需调整需重新配置);
- **生效模型:项目生效 = 通用代码库 + 项目自定义等级 − 项目屏蔽**;变更即时生效并联动全局计数。

## 7.2 故障记录生成与归并

- **项目运维故障**:同一对象的同类故障,持续期间为**一条记录**(故障发生时间=本次开始);异常消失后转「已恢复待确认」;闭环后同类故障再次发生生成**新记录**;
- **空调故障**:同一内机+同一故障码,**同一自然日内**重复上报归并为一条(更新最后上报时间),跨自然日生成新记录(与按日统计口径一致);**故障码复位上报即记录故障恢复时间**,状态转「已恢复待确认」。

## 7.3 短信推送内置去重(后台内置规则)

- **规则**:同一对象(设备/电表/内机)的同一故障,**仅首次发生时推送**;故障恢复(异常消失/故障码复位)前不重复推送;恢复后再次发生视为**新故障**,可再次推送;处理/忽略后同类故障复发同理(重新告警并可再次推送);
- **实现要求**:后台默认执行,**不提供配置项,页面亦不展示规则提示语**(规则仅记录于本文档);仅作用于短信通道,不影响平台内记录与统计(记录归并见 7.2);不设 24h 频控,不设根因抑制。

## 7.4 站内提醒(铃铛)说明

- **不单独建设站内信/消息中心**,站内提醒由顶部铃铛红点承担(见 4.2);
- 红点=「未处理总数」>0(全局口径,含已恢复待确认;项目屏蔽码记录不计),不依赖任何推送配置;
- 红点不设"已读"状态:处理/忽略故障即消数,数字随处理进度实时下降;
- 短信推送记录中不产生站内提醒流水。
